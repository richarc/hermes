# Demo mode

- Demo mode records the app driving itself: `HERMES_DEMO=<script>` at launch (nothing in the app can set it, so production builds honour it too) makes `demo.go` parse the script — one `verb arg` per line (`open`, `goto`, `pause`, `type`, `menu`, `chart`, `table`, `fullscreen`, `record`, `stop`, `quit`), `type`/`chart`/`table` take a body up to a lone `.`, paths relative to the script — and refuse to start on the first bad line. The frontend asks for it once mounted (`DemoService.Script()`; Go cannot know when the page is ready to be pushed to) and `lib/demo.ts` plays it against actions `App.svelte` builds from the same functions the menus call, so the recording shows what a person would see. `fullscreen` (no argument) enters macOS full screen and does not return until the window reports it is there, because `record` measures the window's bounds as it starts — put it before `record`, with a short `pause` after it so the recording does not open on the tail of the animation; `record`/`stop` run `screencapture -v -R <window bounds>` from Go and stop it with SIGINT; a recording still running at quit is stopped by `OnShutdown`. The sample is `docs/demos/chart.demo`, and `TestShippedDemoScriptsParse` keeps it parsing. Launch with `open -n "bin/Hermes Editor.app" --env HERMES_DEMO=$PWD/docs/demos/chart.demo` so macOS asks Hermes, not the terminal, for the Screen Recording permission.
- **Screen Recording permission is bound to the app's code signature, not its name.** `wails3 task package` ad-hoc signs, and an ad-hoc signature is a new identity every build, so each repackage silently invalidates the grant: `screencapture` exits at once, the `record` step fails, and System Settings still shows Hermes Editor switched on — a stale entry for the old signature, which macOS will not re-prompt over. The root `package` task's final signature therefore uses the Developer ID when the keychain has one (`bundle:licences` in `Taskfile.yml`; ad-hoc only as a fallback); its designated requirement is the bundle id plus team, which every build shares, so one grant then lasts. Check with `codesign -dv --verbose=2 "bin/Hermes Editor.app" 2>&1 | grep Authority` before blaming the permission. If the grant is stale anyway, `tccutil reset ScreenCapture com.qxquantum.hermes` clears it and the next `record` posts a fresh request. Confirm in the log: `/usr/bin/log show --last 5m --predicate 'process == "tccd" AND eventMessage CONTAINS "ScreenCapture"'` says "Failed to match existing code requirement" for a stale grant (the plain `log` is a zsh builtin).
- **Never use the prompt's "Quit & Reopen".** It relaunches by bundle id, which LaunchServices resolves to `/Applications/Hermes Editor.app` — the installed release, without `HERMES_DEMO` and without whatever was just built. Choose "Later", quit, and launch `bin/` again with the `open` command.
- **`screencapture` never overwrites.** It records to `~/Library/Group Containers/group.com.apple.screencapture/ScreenRecordings/` and moves the file into place at stop, and that move fails if the path exists — the log line is "Failed to move screen recording … already exists". `StartRecording` removes the target first for that reason; if a recording is missing after a run, look in that folder before re-recording.
- **Verifying a recording is the new one:** `ls -lT docs/demos/<name>.mov` must be newer than the launch, and `mdls -name kMDItemDurationSeconds` on it should match the script's length. The app does not quit at `stop`, so a script that ends there leaves the window open for the person to close.
