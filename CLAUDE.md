# CLAUDE.md

## Project Overview

Hermes is a desktop app built with **Wails v3 (beta)** — `v3.0.0-beta.12`, pinned identically across `go.mod`, the `wails3` CLI and `@wailsio/runtime`, which must be bumped together: a Go backend with a Svelte 5 + TypeScript + Vite frontend rendered in a native webview. The Go module is named `hermes`, so generated bindings live under `frontend/bindings/hermes`.

## Commands

Wails v3 uses [Task](https://taskfile.dev) for orchestration; `wails3 task <name>` and `task <name>` are equivalent. The root `Taskfile.yml` dispatches `build`/`package`/`run` to the platform-specific Taskfile in `build/<GOOS>/`.

- `wails3 task common:generate:bindings` — regenerate the TypeScript bindings in `frontend/bindings/`
- `go test ./. && go build -o /dev/null .` — run Go tests and verify build (use `.` not `./...`)
- `wails3 task package` — rebuild the distributable `bin/<app>.app` bundle. **`build` does not package.** `build` refreshes only the bare binary in `bin/`; the `.app` around it is stale until `package` runs, so copying that bundle anywhere ships whatever was last packaged. Same family of trap as the `run` one below.
- `wails3 task run` — build and launch the app. The `run` task in `build/darwin/Taskfile.yml` has `deps: [build]`, but that is a **hand edit to a generated file**: Wails' own template has no deps, so `run` only copied the existing `bin/Hermes Editor` into the `.dev.app` bundle, re-signed it and launched it — after editing source, it silently launched the previous binary. `update:build-assets` regenerates that Taskfile and will drop the line; re-add it, and until then use `wails3 task build && wails3 task run`. Either way, before reporting that a change works in the app, confirm the binary actually contains it (`strings "bin/Hermes Editor" | grep <a new symbol>`, or compare `ls -lT "bin/Hermes Editor"` against the source mtimes).
- `wails3 task run DEV=true` — the build to use whenever **Safari's Web Inspector** is needed (profiling, console, network tab). The default `build` and `run` pass `-tags production`, under which Wails compiles its devtools out and `inspector_darwin.go` is excluded, so the app is absent from Safari's Develop menu however long you look. Two things have to be true for it to appear: WebKit's `developerExtrasEnabled` (Wails sets it in dev builds) and the WKWebView's `inspectable` property (Wails never sets it on macOS; `inspector_darwin.go` does, from a `WindowDidBecomeKey` hook). The first dev build recompiles every cgo object and takes ~20 minutes; after that the Go cache makes it seconds. `strings "bin/Hermes Editor" | grep -c developerExtrasEnabled` is 1 for a dev build and 0 for production. The render pipeline carries User Timing measures (`lib/perf.ts`: `hermes:render`, `hermes:preview-dom`, `hermes:hydrate-*`) — read them with `performance.getEntriesByName('hermes:render')` in the Console, since a Timeline export keeps the marks but drops the measures.

## Architecture

The core Go↔JS boundary works like this:

1. **Services**: Go structs (e.g. `DocumentService` in `documentservice.go`) are registered in `main.go` via `application.NewService(...)` in `application.Options.Services`. Their exported methods become callable from the frontend.
2. **Generated bindings**: `wails3 generate bindings` scans registered services and emits typed TS wrappers into `frontend/bindings/` (imported as `../bindings/hermes` in `App.svelte`). Never hand-edit these files — regenerate them after changing a service's API. The build tasks regenerate them automatically.
3. **Frontend pipeline** (editor and preview):
   - `lib/renderer.ts`: markdown-it + KaTeX plugin; renders markdown to HTML; intercepts `vega-lite` code blocks as chart placeholders; citations are parsed by `lib/citations.ts` (markdown-it rule + citeproc-js formatter), bibliography data comes from a frontmatter-named `.bib` read/watched through Go (`bib:changed`), and Zotero insertion uses BBT's CAYW via `PickCitations`. `lib/toc.ts` (core rule after `source_line`) gives every heading a slug id and, when the frontmatter says `toc: true`, renders the contents list at the first `[[toc]]` paragraph or the top (`toc-depth` filters, default 3).
   - `lib/figures.ts`: a markdown-it core rule (`figurePlugin`) that decides what counts as a figure — a Vega-Lite `title` or an image's non-empty alt text is a caption, and a caption is what makes a figure — and numbers them in document order. It does the `<figure>`/`<figcaption>` token surgery itself for images; for a chart it only stamps the caption and number onto the fence token, since `renderer.ts`'s fence renderer already hand-builds that block's HTML and reads the stamp back out. It also owns the two document-wide settings' vocabulary (`ChartWidth`, `FigureAlignment`) and `cssTextAlign`, the sole place Hermes' own `centre` spelling is mapped to CSS's `center`.
   - `lib/charts.ts`: Vega-Embed integration; hydrates chart placeholders with live SVG charts; caches embedded specs for efficiency. `vega-embed` is imported dynamically (`await import('vega-embed')`), not statically, from both call sites — that is load-bearing for startup bundle size, so don't convert it to a static import.
   - `ChartBuilder.svelte`: the graphical chart editor opened from Insert → Chart… or the toolbar; pastes/imports a table via `lib/dataTable.ts` (delimited-text parsing and type inference) and encodes it with `lib/chartSpec.ts` (`buildSpec`/`readSpec`, the `BuilderState` <-> Vega-Lite JSON round trip). `App.svelte`'s `openChartBuilder`/`commitChart` decide insert-vs-replace from `Editor.svelte`'s `enclosingChartBlock`, and re-validate the target range against the live document at commit time before writing, since the modal does not block keyboard input to the editor behind it. `TableBuilder.svelte` follows the same open/commit shape for GFM tables — `Editor.svelte` passes `extensions: [Table]` from `@lezer/markdown` to `markdown()`, which is what makes `enclosingTable` possible; `lib/pipeTable.ts` parses and serialises (padded, with alignment; cells are raw markdown source); and `commitTable` re-validates the range by comparing the live text against what was captured when the builder opened, rather than by re-parsing it — the same guard `commitChart` applies before writing.
   - `lib/markdownCommands.ts`: editor formatting as pure CodeMirror `StateCommand`s, invoked from the Format menu via the `menu:format` event and guarded by `isProtected` so they never rewrite fenced code or frontmatter. Accelerators are owned by `menu.go`, because AppKit dispatches menu key equivalents before the webview sees them — *except* for chords CodeMirror's `defaultKeymap` already claims with `preventDefault` (⌘I is `selectParentSyntax`, ⌘⇧K is `deleteLine`). The webview wins those, so `Editor.svelte` re-binds them at `Prec.highest` and routes them back through App's `applyFormat`. Check `defaultKeymap` *and* `foldKeymap` before adding an accelerator — `foldKeymap` claims ⌘⌥[ and ⌘⌥] for folding, which the View menu reflects rather than re-binds, since the keystroke already does what the menu item says.
4. **Events (Go → JS)**: Go emits events with `app.Event.Emit(name, data)`; the frontend subscribes with `Events.On(name, cb)` from `@wailsio/runtime`. Hermes emits `menu:new`, `menu:open`, `menu:open-recent` (path payload), `menu:insert-citation`, `menu:insert-chart` and `menu:insert-table` (from the Insert menu), `menu:save`, `menu:save-as`, `menu:export-pdf` (payloadless — export needs the document's path, which only the frontend holds, so the menu asks rather than calls), `menu:check-updates` (payloadless — the frontend owns the dialog and toast that report the result), `menu:format`, and `menu:fold` (both command-name payloads) from `menu.go`; `close:confirm`, `recents:changed`, and `settings:changed` from `main.go`; and `bib:changed` from the bibliography watcher. These are plain, untyped events — there is no `application.RegisterEvent[T](name)` registration step in `main.go` (or anywhere else), so the frontend types each payload manually where it calls `Events.On`.
5. **Asset embedding**: `frontend/dist` is embedded into the binary via `//go:embed all:frontend/dist` in `main.go`, so the frontend must be built before the Go binary is (the Taskfiles handle this ordering).

Other things to know:

- **Editing the long prose documents** — `ROADMAP.md` (700+ lines), `README.md`, `CHANGELOG.md`. Scripted edits that splice by string index have corrupted `ROADMAP.md` twice, both times pushed before anyone noticed. The failure is always the same shape: `start = s.index(a)` and `end = s.index(b)` where `b` occurs *earlier* in the file than `a`, so `s[:start] + new + s[end:]` emits everything between them twice. Ticking a roadmap item is exactly this pattern, because the replacement text and the surrounding entries look similar. So: assert the boundaries are ordered (`assert end > start`) before splicing, prefer replacing one unique block with `str.replace` and `assert s.count(old) == 1` over index arithmetic, and check the shape afterwards — `grep -c '^- \['` before and after should differ by exactly what you intended, and `grep '^## '` should be unchanged. The same care applies to any regeneration: verify the region you are about to overwrite, not just the result.
- The licence texts are copied into `Contents/Resources/licences` by `bundle:licences` in the **root** `Taskfile.yml`, which the root `package` task runs after the platform one. A distributed binary has to carry them: Apache-2.0 §4(d) requires `NOTICE` to travel with the work, and citeproc-js is dual CPAL/AGPL, both of which require their licence to accompany the distribution — having them in the repository covers source distribution only. It lives in the root Taskfile because `build/<GOOS>/Taskfile.yml` is regenerated by `update:build-assets` and the root one is not. The task **re-signs afterwards**, because `codesign` seals `Contents/Resources` and files added later invalidate the signature; that matters more once signing with a Developer ID rather than ad-hoc.
- Opening a local path from Go uses `app.Browser.OpenFile(path)`, never `OpenURL("file://"+path)` — the bundle name contains a space, so a hand-built file URL is malformed. Both end at `exec.Command("open", target)`, and the implementation discards the result in a goroutine, so **a bad target fails silently**: only a failure to start `open` is returned. Budget for that when debugging anything that opens a file or URL.
- The application is named **Hermes Editor** — `APP_NAME` in the root `Taskfile.yml`, which names the bundle (`bin/Hermes Editor.app`), the binary inside it, and `CFBundleExecutable`. macOS names an app by its bundle filename, so `CFBundleName` alone was not enough: the bundle read as "hermes" in Finder and the Dock while the plist said otherwise. The space means paths must be quoted — the macOS build, package and run tasks already quote every use, but the docker and server tasks in `build/Taskfile.yml` do not, so they would need quoting before they are used.
- App metadata (name, version, product identifier) lives in `build/config.yml`; after changing it, run `wails3 task common:update:build-assets` to regenerate build assets (this overwrites manual edits to those assets).
- The app icon is a **layered Icon Composer icon**. `build/appicon.icon/` holds `icon.json` and two SVG layers copied from `build/icon/`; `wails3 task common:generate:icons` compiles them into `build/darwin/Assets.car` with `/usr/bin/actool`, which needs a full Xcode 26+ and `xcode-select` pointed at it, not at Command Line Tools. In `icon.json`'s `layers` array the **first entry is the top of the stack** — `plates` above `paper`. actool generates the light, dark and tintable appearances itself from those layers (confirmed with `assetutil --info`), so the dark-ground SVG in `build/icon/` is reference artwork rather than an input.
- `Info.plist` must declare `CFBundleIconName` **only while `Assets.car` exists**. macOS 26 prefers that key over `CFBundleIconFile`, and a dangling value leaves the app with **no icon at all** in Finder and the Dock while the bundle is otherwise perfectly valid — icns present, signature good, LaunchServices happy. That cost an afternoon on 2026-08-23. `update:build-assets` adds the key when `Assets.car` is present and updates existing keys but never deletes extra ones, so removing `Assets.car` means deleting the key from `build/darwin/Info.plist` and `Info.dev.plist` by hand.
- `build/appicon.png` (1024×1024) still feeds `build/darwin/icons.icns` and `build/windows/icon.ico` for the non-layered paths. It is rendered from `build/icon/HermesIcon.svg` with `qlmanage -t -s 1024 -o <dir> build/icon/HermesIcon.svg` — QuickLook uses WebKit, so the `mix-blend-mode: multiply` the three plates rely on renders correctly, which most SVG rasterisers would flatten into a plain cyan H. The artwork carries its own `rx="230"`, close to Apple's squircle proportion, so nothing else should round it. Note also that `create:app:bundle` never cleans `bin/<app>.app`, so a stale `Assets.car` survives repackaging; `rm -rf "bin/Hermes Editor.app"` before `wails3 task package` when a Resources file has been removed.
- Persisted preferences all live in the single `Settings` struct in `settings.go`, behind the `Settings`/`UpdateSettings` binding pair. Adding one is a field with a `json` tag, a default in `defaultSettings`, and a clamp in `normalise`; persistence, the `settings:changed` event, the menu rebuild, and the TS model all follow with no extra wiring. `settingsStore` reads the file once and writes only on a real change, so don't reach for the file directly.
- Recovery drafts are `recovery.go` (a `draftStore` under `<data>/hermes/drafts/`, keyed by a hash of the document path, `untitled` for none) behind `WriteDraft`/`DiscardDraft`/`RecoverDraft`, and `lib/recoveryDraft.ts` decides *when*: debounced 2 s while dirty and `autoSave` is on, discarded on the dirty-to-clean transition, both through one ordered queue so a discard cannot overtake a write in flight. `App.svelte` awaits `settle()` before quitting for the same reason. Go decides whether a draft is still worth offering (`find`: dropped if the document's mtime is at or after the draft's, or the texts match) — keep that rule in Go, so the frontend never compares files. A draft is never written over the document; explicit Save remains the act of record.
- The update check is `update.go`: `CheckForUpdates(force)` GETs the bare feed URL (`updates/latest.json` on `main`, via raw.githubusercontent.com) with no query string and no custom header, at most once per 24 h through a timestamp in `<data>/hermes/update-check.json` written before the fetch, validates the version as `MAJOR.MINOR.PATCH`, and **derives** the release URL from it — the feed is never trusted for a destination. `force` (Help → Check for Updates…) skips both the setting gate and the throttle. The feed, the release guard in `Taskfile.yml`, and the push-last ordering in README's release steps are one contract: bump `config.yml` and the feed together, publish, then push. The three-state `updateCheck` setting is asked about once at first launch in `App.svelte`, after the recovery-draft offer and never over it.
- Spell checking is native WebKit, scoped by attribute: `lib/spellcheck.ts` sets `spellcheck="true"` on the content element and wraps `protectedRanges` (code/URL/HTML from the syntax tree, frontmatter by line, maths and citations by pattern) in `spellcheck="false"` marks, which WebKit honours per element. `Editor.svelte` holds it in the editor's only `Compartment`, driven by the `spellcheck` prop from the `SpellCheck` setting. WebKit's continuous-checking flag has no registered default in a WKWebView app, so `spellcheck_darwin.go` registers `WebContinuousSpellCheckingEnabled` on before the window exists; do not move that call after `application.New`. Coverage is WebKit's: it checks the word typed and the word the caret leaves, never a loaded document — see the roadmap item before treating "no underlines on open" as a bug. `autocorrect` stays off.
- PDF export (`print_darwin.go`) runs `NSPrintPanel` **before** creating the `NSPrintOperation`, and this ordering is load-bearing. Creating the operation first — which is what Wails' own implementation does — makes `WKPrintingView` paginate against the print info supplied at that moment; the panel then substitutes the chosen printer's paper size and imageable area, the content reflows, and the operation still renders only the pages it originally counted, silently dropping the tail of a long document. The cost is that the panel has no live preview, since the preview is drawn by the operation; `NSPrintPanelShowsPreview` on a standalone panel does nothing. Also note `[po runOperation]` deadlocks on the main thread — `WKPrintingView` needs the runloop to service the web content process, so use `runOperationModalForWindow:`.
- Images stored beside the document are served by `localimages.go`, registered as `AssetOptions.Middleware` in `main.go`. The webview loads the embedded bundle, so a document-relative `<img src>` would resolve against *that* and 404 — `renderer.ts`'s image rule rewrites a local source onto `/_hermes/image?doc=…&src=…` and Go joins the pair with `resolveAgainstDoc`, the same package-level resolver `ReadBibliography` uses. Keep `LOCAL_IMAGE_ROUTE` in `renderer.ts` and `localImageRoute` in `localimages.go` in step. markdown-it percent-encodes link destinations before a renderer sees them, so the source is decoded before being re-encoded for the query string; skipping that sends `%2520` and looks for a file with a literal `%20` in its name.
- Links in the preview are intercepted by a delegated click handler in `Preview.svelte` and opened in the system browser via `Browser.OpenURL` from `@wailsio/runtime`; a plain `<a href>` click would otherwise navigate the webview away and destroy the app state.
- Colours live in one place: the custom-property palette at the top of `frontend/public/style.css`, with a `:root[data-theme="dark"]` block that must define exactly the same names. `src/lib/styleContract.test.ts` fails the build if a rule uses a literal colour or if the two blocks diverge. CodeMirror is themed through the same variables (`Editor.svelte`), so switching needs no reconfiguration. The dark `--bg` is duplicated in `main.go` as the window background because Go cannot read the CSS.
- Figure alignment is one attribute, not a class per element: `Preview.svelte` writes `data-figure-align` (`"left"`/`"center"`/`"right"`, via `cssTextAlign`) onto the preview root, and `style.css` matches `[data-figure-align="…"] figure`/`.vega-lite-chart`/`p:has(> img:only-child)`/`p:has(> a:only-child > img:only-child)` off it — the last two are how an uncaptioned (or linked) bare image gets aligned, since it never becomes a `<figure>` at all. Renaming the attribute or its values needs both sides updated together.
